# 0.27 Websocket heartbeat

- Decided by: user (server to browser only), Claude (timings)
- Date: 2026-10-19

The server pings every connection with websocket protocol pings
(`conn.Ping`) every 30 s and closes the connection when no pong arrives
within 10 s. The interval stays below the 60 s idle timeout of common reverse
proxies (nginx `proxy_read_timeout`), so idle connections are not cut.

There is no browser to server heartbeat. Browsers answer protocol pings on
their own and JavaScript never sees them, so the frontend manager needs no
pong handling; its 1 s `readyState` check (from the original) stays and only
notices closes the browser already knows about.

Consequence: the read loop must keep reading while handlers run, because
pongs are only read inside `Reader` (see 0.28, ordered dispatch).
