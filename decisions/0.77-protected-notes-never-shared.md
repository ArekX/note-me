# 0.77 Protected notes are never shared; reminders follow shares

- Decided by: user (a protected note cannot be shared; protecting a shared
  note removes its shares and notifications; a revoked share removes the
  recipient's reminders and notifications); Claude (queries)
- Date: 2026-10-21
- Amends 0.45 and 0.46.

- `shareToUsers` and `createPublicShare` refuse a note with
  `is_encrypted = true`: "Protected notes cannot be shared.". The share
  window shows the same text for a protected note and hides the forms.
- When a note becomes protected (`updateNote` with `is_encrypted: true`, a
  revert to a protected version) `RemoveNoteShares` runs in the same
  transaction: user shares, share links, reminders of users other than the
  owner and their notifications about the note are deleted. The owner's own
  reminder stays. Ciphertext is therefore never handed to a recipient, which
  closes the `getNoteDetails` gap of SF-15.
- `SetUserShare` deletes the reminder and the notifications about the note
  of every user it removes, so a former recipient keeps no title or search
  access through a lingering reminder.
- The reminder queries (`FindUserReminderNotes`, `SearchReminderNotes`,
  `GetReadyReminders`) additionally require that the reminder's user owns
  the note or still holds a share, as a second line.
