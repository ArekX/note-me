# 0.53 Data export and import

- Decided by: Claude (TODO item 16)
- Date: 2026-10-19

Job queue and processor:

- `internal/components/jobs` (on `components.Jobs`) is the queue between
  request handlers and the job processor worker: `Enqueue(name, userID,
  payload)` returns a job id (uuid), `Abort(jobID, userID)` cancels the
  job's context, `Finish` forgets it. The owner registry lives there and is
  cleaned on finish, failure, panic and abort (0.9.o). An unknown job id
  answers like someone else's: "You do not own this export job.". The
  queue holds 64 waiting jobs; more answer "Too many exports are running,
  please try again later.". It is a component rather than part of
  `workers/jobprocessor` because the websocket and the workers do not
  import each other (layers); results still travel back over the event bus
  (0.40).
- `workers/jobprocessor` runs every job on its own goroutine (the original
  ran them concurrently too). A job's context ends when it is aborted or the
  worker stops; `Run` waits for running jobs before returning. Payloads are
  typed structs (`jobs.DataExport`).

Export (`create-data-export`):

- `exportOwnData{user_password}` checks the password first and answers
  "Invalid password." (the original queued the job with any password and
  failed at the first protected note). The export id is a uuid.
- The job writes `temp/data-export-<userId>-<exportId>.zip.partial` and
  renames it to `.zip` when complete (the `.zip` extension is the 0.9.p fix),
  so a download never sees half a zip. Abort, failure and shutdown remove
  the file. The hourly temp cleanup expires finished exports after 6 h.
- Contents as in the original: files first (0–50 %) as
  `file/<identifier><ext>`, files missing on disk are left out; then the
  note tree (50–100 %) from `notes/`, notes as `<prefix>/<title>.md` and
  groups as folders, both with `[^a-zA-Z0-9]` replaced by `-` (name
  collisions kept, 0.9.p). `/file/<identifier>` links in notes are rewritten
  to `/file/<identifier><ext>` for exported files. Protected notes are
  decrypted with the password; the note key is opened once, at the first
  protected note.
- Progress is rounded to two decimals and pushed after each page of files
  and after each group's notes. Fix: the done counter is shared across the
  tree; the original counted per group, so progress went backwards after a
  subgroup. No division by zero for accounts without files or notes.
- Pushes go `eventbus.DataExportUpdated/Finished/Failed` → backend
  `notifyUserExport*` → `exportOwnDataPercentage/Finished/Failed` to every
  tab of the user (the original reached one tab). Failure messages the user
  can act on are passed through (wrong password or corrupted data, old
  encryption format, missing key); anything else is logged and shown as
  "Export failed due to an internal error." instead of the raw error.
- Download: `GET /api/data-export/{identifier}` behind the authenticated
  chain (the original's `/app/profile/download-export-{identifier}` cannot be
  a `ServeMux` pattern, and `/api` is what the dev proxy forwards). The user
  id from the session is part of the file name, so only own exports are
  found; anything else is 404 "Export not found.". `application/zip`,
  `attachment; filename="<identifier>.zip"`, `Cache-Control: no-cache`,
  served with `http.ServeContent` (Content-Length, Range).

Frontend:

- Data tab: `ExportMyData` (confirm → password from the protection lock →
  progress dialog with Cancel → finished dialog with the download link and
  the 6 hour notice; failures as toasts; leaving the page or closing the tab
  cancels a running export) and `ImportNotes` (as the original: one
  `createNote` per file, title = file name, chosen group, progress, "File
  import completed.").
- Fixes: events that arrive before `exportOwnDataResponse` names the export
  are kept and applied once it does (a small export can finish first), and a
  Cancel pressed before the response cancels the job as soon as its id is
  known.
- Mock mode: the dev Vite middleware serves `/api/data-export/<id>` as an
  empty zip; cancelling an unknown mock job fails like the server.
