# 0.86 Rich note editor

- Decided by: user (Tiptap 3 for a rich editor next to CodeMirror, notes
  stay markdown, each user picks the editor in the profile, rich by
  default; extensions shown as labelled blocks that reopen their insert
  dialog; one toolbar for both editors; rich, source and preview always
  selectable in the editor, the profile only picks the starting one);
  Claude (details below)
- Date: 2026-10-21
- Amends 0.38 and 0.81 (toolbar commands).

- Packages: `@tiptap/core`, `@tiptap/pm`, `@tiptap/vue-3`,
  `@tiptap/starter-kit`, `@tiptap/extension-code-block`,
  `@tiptap/extension-code-block-lowlight`,
  `@tiptap/extension-image`, `@tiptap/extension-list`,
  `@tiptap/extension-table`. `@tiptap/markdown` is not used: it parses with
  marked, which disagrees with the viewer (escaped `\*` came back as
  emphasis, raw `<b>` became bold), and it writes every `&`, `<` and `>` as
  an HTML entity.
- Markdown in: `lib/rich-editor/markdown-parse.ts` turns the viewer's own
  markdown-it tokens (`tokenizeMarkdown` in `lib/markdown.ts`) into the
  Tiptap document, so both see the same structure. Markdown out:
  `markdown-serialize.ts` writes it back and escapes only what markdown-it
  would read as syntax. List markers, `*`/`_`, fences, rules and tight or
  loose lists are kept as node attributes, so an unchanged note saves
  unchanged. What still gets normalised: setext headings, `&copy;` (saved
  as ©), two-space hard breaks (saved as `\`), table padding and footnote
  definitions (moved to the end, where the viewer shows them).
- Nodes beyond the starter kit: soft breaks (shown as a space, as the
  viewer does, saved as the line break), `noteExtension` (inline atom
  holding the `{:...}` text), footnote references and definitions. A list
  that mixes tasks and plain items stays a bullet list with the `[ ]` text,
  which the viewer still shows as checkboxes.
- Typing markdown formats in place with Tiptap's input rules plus ours for
  `- [ ] `, links, images, `{:...}`, `[^x]` and `[^x]: `. Pasted plain text
  is parsed as markdown; a copy from the editor itself keeps its structure
  and goes to the clipboard as markdown.
- The mode switch above the toolbar has rich text (pencil), markdown
  source (code) and preview (eye). A note opens in the profile's editor;
  switching keeps the text, and the rich editor only rewrites the markdown
  once something is edited in it.
- Node views: extensions show "Note list: <group>" / "Note link: <title>"
  and reopen `InsertItemDialog` with `initialData`; audio and video are a
  card (`glass-card`) with a header (icon and kind, no address) above the
  player; code blocks are a card with
  a language dropdown (plain text, mermaid and every highlight.js language
  from `lib/code-languages.ts`, which the supported languages help page
  also uses; an alias like `js` is shown as its language and only rewritten
  when another one is picked, an unknown one is kept as an extra option),
  and mermaid blocks have a Code / Diagram / Split switch at the right of
  the header (view only, not saved). It starts on Diagram, or on Split
  when the block is empty so there is somewhere to type; switching to
  Diagram while the cursor is in the hidden code selects the block. Clicking the card
  outside the code (border, padding, header, diagram) selects the whole
  block like the audio card (copy, Backspace deletes); clicking the code
  places the cursor. Code is
  highlighted while editing by Tiptap's lowlight plugin, fed by
  `lib/rich-editor/code-highlight.ts` with the viewer's highlight.js
  instead of the `lowlight` package (its `all` grammars were a second copy
  of highlight.js, about 300 kB gzipped); blocks without a known language
  stay plain like in the viewer. Token colours are `--color-code-*` theme
  tokens in `styles.css`, used by the viewer too (it had no highlight
  colours before).
- The toolbar has a code block button next to inline code: the rich editor
  toggles a code block, the source editor fences the selection or opens an
  empty block.
- `EditorToolbar` emits tool ids from `lib/editor-tools.ts`; the source
  editor maps them in `lib/codemirror/toolbar.ts`, the rich one in
  `lib/rich-editor/commands.ts`. In the rich editor link and image open a
  small dialog instead of inserting placeholders. Keyboard shortcuts come
  from the same `noteTextAreaHotkeys`; the note editor's Ctrl+S and Ctrl+E
  pass through (Tiptap's Mod-e for inline code is switched off).
- `RichTextArea` is loaded with `defineAsyncComponent`, so Tiptap is its
  own chunk.
- `user.preferred_editor` (`rich` / `source`, default `rich`) is in the
  initdb migration for every driver; `noteme-upgrade` adds it with the
  default for existing users. It is sent as `preferred_editor` in the
  session and `sessionUpdated` user, and `updateProfile` takes it as an
  optional field (absent keeps the current value).
