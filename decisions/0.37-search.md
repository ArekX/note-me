# 0.37 Search

- Decided by: Claude (TODO item 5)
- Date: 2026-10-19

- Search state is the Pinia setup store `stores/search.ts`
  (`useSearchStore`), not a module-level composable; it registers its
  websocket listener once through `init()` like the tree store, called from
  `Sidebar`. Later items add their responses to that listener.
- The store is built on `useFilters` (250 ms debounce for search, 500 ms
  default) and `useLoadMore` (pages of 10, `from_id` = last record id,
  `hasMore = len >= limit`); `useDebouncedCallback` backs `useFilters`. The
  filter factory (`TextFilter` / `DropDownFilter`) is not built here: no
  search component uses it. It comes with its first user, `UserList`
  (item 17).
- Fix over the original: a filter change while a search was running was
  ignored and the old response was appended to the new list. Now
  `useLoadMore.reset()` drops the running load's records and the new search
  starts at once.
- The group filter keeps `{id, name}` instead of a whole `TreeRecord`.
  Picking a list in `ListSwitcher` calls `setType`; the original called it
  when each list mounted.
- `NoteSearchRecord.group_name` is nullable: `null` for a note with no group,
  as the original returned at runtime (same as 0.34). Search does not
  normalise filter tags; `TagInput` already sends them normalised.
- `searchNote` answers `[]` for an unknown type and, until items 7, 11 and
  12 add them, for `recycleBin`, `reminders` and `shared`.
