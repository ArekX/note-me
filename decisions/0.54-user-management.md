# 0.54 User management

- Decided by: Claude (TODO item 17)
- Date: 2026-10-19

- `createUser`, `updateUser`, `deleteUser` and `findUsers` require
  `canUpdateUsers`, checked before validation. Validation follows
  `addUserSchema` / `updateUserSchema` with zod's messages (role enum:
  `Invalid option: expected one of "admin"|"user"`, timezone as in 0.47).
- Creating a username that belongs to a deleted user revives that account:
  its notes and files come back, and it gets the new name, role, timezone
  and password. Fix: the original ignored the password on revival, so the
  account kept its old password; now the new password applies, with a new
  note key and a required password change like any admin-set password
  (0.9.t).
- `updateUser` pushes the changed user's session to their open tabs right
  away (`RefreshUserSession`, 0.9.n). Not in the original, whose form only
  hid the fields: an admin cannot change their own role ("You cannot change
  your own role.") or set their own password here ("Please change your
  password via profile page."). An unknown or deleted user answers "User
  not found.". The response no longer echoes `new_password`.
- `deleteUser` refuses the own account ("You cannot delete your own
  user."), soft-deletes the user and removes their sessions and passkeys in
  one transaction (0.50), then `hub.LogoutUser` sends
  `users/forceLogoutResponse` to every open connection of the user (the
  original reached one) and closes them, so a tab that ignores the message
  keeps no access. The frontend's logout page clears local storage.
- `findUsers`: name and username contain (LIKE escaped, trimmed), role
  exact, deleted users left out, ordered by id, 20 per page.
- Frontend: Settings → Users with `UserList` (filters in the `Table`
  filter row, debounced 500 ms by `useFilters`; no separate filter factory
  or filter components, `Input` and `DropdownList` are used directly) and
  `EditUserForm` (username only for new users, own role locked, own
  changes through `updateProfile` as in the original). Fixes: the "Set new
  password" errors show for existing users (the original looked at the
  wrong path), and a cleared password field sends no password instead of
  "", which failed the 8 character rule and blocked saving.
