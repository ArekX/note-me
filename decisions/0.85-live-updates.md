# 0.85 Live updates from every source

- Decided by: user (TODO item 31 design, built before item 29); Claude
  (details below)
- Date: 2026-10-21
- Extends 0.6 (push fan-out) and 0.40 (event bus).

- **Acting user**: every handler that changes data answers with
  `RespondToUser`, so the user's other tabs get the response as the event:
  notes, groups, reminders and history as before, and now files (`endFile`,
  `updateFile`, `updateMultipleFiles`, `deleteFile`), tags, sharing
  (`shareToUsers`, `createPublicShare`, `removePublicShare`), notifications
  (mark read, delete), users admin, profile, onboarding, passkeys, backup
  targets and backups. Message types and fields are unchanged. Failures
  that change nothing (a failed manual backup, a failed passkey
  registration) still answer only the requesting connection.
- **Other users**: `changes/dataChanged` (`messages/changes.go`,
  `types/messages/changes.ts`) with `entity` and `ids`. Ids are numbers, or
  strings for entities keyed by an identifier (files, backups, periodic
  tasks). Recipients:
  - a note's share recipients when its owner edits, reverts, deletes,
    restores or deletes it for good (looked up before the change, since
    protecting or deleting removes the shares); entity `note`. A deleted
    folder sends one message per shared note in it, so recipients learn no
    ids of the owner's other notes;
  - old and new recipients when the user list of a share changes; entity
    `share`. Public link changes only reach the owner's tabs, since
    recipients never see links;
  - tags: every other connected user;
  - users created, changed (also through their own profile) or deleted:
    other admins (`canUpdateUsers`);
  - backup targets and backups: other admins (`canManageBackups`);
  - files: the owner when an admin changes their file, and the other
    admins with `canManageAllFiles`.
- **Hub**: `SendToUsers(ctx, userIDs, msg)`, `SendToPermission(ctx,
  permission, except, msg)` and `SendToEveryone(ctx, except, msg)`, over
  connected clients only; the permission comes from each connection's
  session and `except` skips the acting user.
- **Workers** publish typed events (`ReminderTriggered`,
  `PublicShareExpired`, `AutomaticBackupFinished`, `PeriodicTaskRan`); the
  owning namespace (notes, settings) turns them into the backend message
  `changes/notifyDataChanged` (user ids or a permission), which the
  `handlers/changes` namespace sends as `dataChanged`.
  `RemoveExpiredPublicShares` returns the notes whose links expired.
- **Frontend**: `useDataChanges(sources, reload, options)` replaces
  `useNoteChanges`. It listens to the responses of each source and to
  `dataChanged`, batches reloads (100 ms), and while the browser tab is
  hidden only marks the list stale and reloads once it is shown (hidden
  sidebar panels and settings tabs are unmounted). Options: `responses:
  false` for lists of other users' data (shared with me), `skipOwnRequests`
  for lists that reload after their own actions, `matches` to narrow
  `dataChanged` to the shown ids. `passkey` is a frontend-only source. The
  socket service remembers the request ids it sent (`isOwnRequest`), so a
  tab tells its own responses from changes made elsewhere. The search and
  notifications stores follow the same messages.
- **Open note**: a change from elsewhere (not this tab's request) while
  the editor has unsaved edits shows "This note was changed elsewhere."
  with **Reload** (take the stored note) and **Keep mine** (the next save
  overwrites). Without unsaved edits, new text reloads the note, so it
  replaces the editor content and is decrypted when protected; other
  fields update in place. The viewer reloads for protected text and
  updates in place otherwise. A delete still closes the note.
- No source field on events.
