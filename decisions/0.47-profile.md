# 0.47 Profile

- Decided by: Claude (TODO item 13); user (old password required for a
  password change)
- Date: 2026-10-19

- `users/updateProfile` validates like `userProfileSchema` in zod 4: field
  rules, then the two password refinement issues on `new_password` and
  `confirm_password`. zod still runs the refinements after `too_small`
  issues but not after an invalid enum value, so an unknown timezone gives
  only the field issues. zod's enum message lists every allowed value; that
  list is the browser's (`Intl.supportedValuesOf`), so the server answers
  "Invalid option: expected one of the supported timezones" and checks the
  zone with `internal/timezone`.
- A wrong old password answers "Old password is incorrect", the same old
  and new password "New password must be different from the old
  password.". Changing the password re-encrypts the note key (0.14), so
  protected notes stay readable with the new password.
- The response echoes only name and timezone (0.9.k). Every tab of the user,
  the requesting one included, gets `sessionUpdated` before the response
  (`RefreshUserSession`); the user store also applies the response.
- An unlocked protection lock is re-primed with the new password after a
  password change (0.42); a locked one asks for the new password next time.
- Changed on the user's request: a new or confirm password sent without
  the old password is a `custom` issue on `old_password`, "Old password is
  required to change the password." (frontend `userProfileSchema` and the
  server). The original saved name and timezone and silently skipped the
  password change.
