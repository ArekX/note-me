# 0.49 Passkeys rewrite

- Decided by: user (passkeys of the original app are dropped, no support for
  both formats; table changes through a new migration that `noteme-upgrade`
  also accounts for); Claude (schema details)
- Date: 2026-10-19

- Passkeys are stored the way go-webauthn needs them, so passkeys registered
  in the original app are not carried over. Users register them again;
  username and password stay required for every user and passkeys remain an
  extra way to sign in.
- Migration `20261019_123255_passkey_security` (decision 0.52):
  - drops `user_passkey.webauthn_user_identifier` and its
    `(user_id, webauthn_user_identifier)` index;
  - adds `user_passkey.is_backup_eligible` and a unique index on
    `credential_identifier` (one credential can belong to one account
    only), plus an index on `user_id`;
  - adds `user.passkey_user_handle` (unique): one random 64 byte WebAuthn
    user handle per user, created at the first registration, base64url.
    The original made a new handle for every passkey; one per user lets
    password managers replace a passkey of the same account instead of
    adding another.
  - Its down migration restores the old column with the credential id as
    value, since the old handles are gone.
- `noteme-upgrade` deletes every passkey of an original database before the
  migration runs and prints how many it removed. It only does so while
  `user_passkey` still has `webauthn_user_identifier`, so a second run, or a
  run after the migration, keeps passkeys registered with the new code.
- Credential ids and the user handle are stored as unpadded base64url text,
  the public key as the COSE blob, the signature counter, both backup flags
  and the transports (comma separated) as before.
