# 0.72 Users are deleted for good

- Decided by: user (no soft delete; deleting a user removes everything of
  theirs from the database); Claude (what happens to shared tags and the
  audit log, upgrade of old databases)
- Date: 2026-10-21
- Replaces the revival of 0.54 and the soft delete it relied on.

- `deleteUser` runs `DeleteUserRecord(id, tagOwnerId)`: in one transaction
  the user's notes go the way `FullyDeleteNotes` removes them (tags links,
  group links, history, reminders, share links, user shares and every
  notification about them, other users' included), then their reminders and
  shares on other users' notes, group links, groups, file records,
  notifications, sessions and passkeys, and the user row itself. The handler
  removes the returned file identifiers from `FILES_LOCATION` afterwards and
  logs every open tab out as before.
- Tags are global (0.44): a tag the user created stays when another note
  still uses it and is handed to the administrator who deleted the user;
  unused ones are deleted.
- The audit log (0.74) keeps its entries: `audit_log.user_id` has no foreign
  key and the username is stored as text, so what an administrator did to a
  deleted account stays on record.
- `user.is_deleted` stays in the schema (0.61) but is never set and no query
  filters on it. Creating a username that exists answers "User with this
  username already exists." whatever its history. `createUser` no longer
  revives.
- `noteme-upgrade` deletes users of an original database that were soft
  deleted, with the same cleanup, and the server refuses a database that
  still has `is_deleted = true` rows until it ran.
