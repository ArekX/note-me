# 0.65 Redesign applied: icon rail in Aurora night

- Decided by: user (the design from the 0.64 lab: rail layout A in style 6
  "Aurora night", darker than Aurora glass, no gradients, less rounded,
  rail labels as tooltips, settings only in the user menu, notifications
  next to the user at the bottom, "Lock" / "Unlock" in the user menu, a solid
  user menu, cards and panel in the same dark tint, the note full width with
  its actions top right, context aware add buttons, home, note edit,
  administration, profile and help pages with their dialogs; Plus Jakarta
  Sans self hosted; on a phone Reminders, Shared with me and Recycle bin are
  rows in the user menu; real owner, type and visibility filters for files;
  pages outside the design restyled too); Claude (details below)
- Date: 2026-10-20
- Applies 0.64; the lab is deleted.

- Theme: the colours, font and shadow are Tailwind theme tokens in
  `src/assets/styles.css` (`bg-surface`, `bg-surface-2`, `bg-menu`,
  `bg-field`, `border-line`, `border-line-strong`, `text-fg`, `text-muted`,
  `bg-accent` / `text-accent-ink`, `*-danger`, `*-success`, `*-warning`,
  `shadow-float`). Shared components use them instead of raw greys; a bare
  `border` is `line`. The app background is the monthly wallpaper under a
  flat `overlay` (`.app-backdrop`); `.glass` adds the blur. Scrollbars are
  thin (standard properties in Firefox, `::-webkit-scrollbar` elsewhere,
  because Chromium ignores those once `scrollbar-color` is set).
- Font: Plus Jakarta Sans variable woff2 (latin, latin-ext, both styles) in
  `public/fonts` with its OFL licence; nothing is loaded from Google.
- Buttons keep their colour names: `success` is the solid accent (main
  action), `primary` the secondary look, `transparent` the icon/ghost
  button, new `transparentDanger` for delete icons in rows. Cancel and Close
  are never red. `ButtonGroup` is a segmented control; `TabPanel` uses the
  new `TabStrip` (underline tabs, scrolls with touch and wheel, fades the
  edge with more tabs, scrolls the picked tab into view). `Dialog` has a
  header with a close button when it can be cancelled and a body that fades
  at the edges; on a phone it opens as a bottom sheet. `PageHeader` holds a
  page title, its explanation and its main action.
- Desktop layout: `AppRail` (home, Notes, Search, Reminders, Shared with
  me, Recycle bin; lock, notifications, user menu at the bottom; tooltips)
  and the panel `Sidebar` (the picked list with its header, actions and
  search bar; picking the open item again or the chevron hides it). State is
  in `useSidebar`. The search bar searches the list that is open, as before;
  Search focuses it.
- Phone layout: `PhoneTabBar` (Home, Notes, Search, Notifications and your
  initials, without labels). Notes, Search and Notifications open the panel full screen
  (`useMobileMenu`); any route change closes it. The last tab shows your
  initials and opens `UserMenu` in a `BottomSheet`.
- Removed: `SidebarMenu`, `SidebarMenuTop`, `ListSwitcher`,
  `NotificationList` (bell popover), `EncryptionLockButton` (logic in
  `useProtectionToggle`), `HelpButton`, `EditTagForm` (tags are renamed
  inline).
- Add buttons above the tree: the tree store keeps a `selectedKey` set by
  clicking a node; a selected group is the target, a selected note's parent
  group otherwise, the top level when nothing is selected. Clicking the
  empty part of the tree clears the selection, which is how to get back to
  the top level.
- Files pages use `FileManager` (table, view dialog, upload, delete);
  `FilePicker` (grid, used to insert files) shares the logic through
  `useFileList`. `findFiles` takes optional `owner` (name or username, only
  with `allFiles`), `kind` (`image`, `document`, `other`, by mime type; the
  same rules are in `src/lib/file-kind.ts`) and `visibility` (`public`,
  `private`). Unknown values do not filter. The owner filter is a text field,
  not a list of users, so it needs no user lookup.
- Help and onboarding texts point at the rail and the user menu instead of
  the old sidebar icons.
- Review against the design (user asked for it, and for the missing glass):
  cards, tables and other panels use `.glass-card` (surface, line border,
  blur, `shadow-card`); toasts use `.glass-menu`;
  every menu that pops up (dropdowns, the tag suggestions, the user menu,
  editor autocomplete) and dialogs are solid (`.popup-menu`, user). Base text is 15px with
  line height 1.55 and tabular numbers, as in the design.
- `AppTopBar` above every app page: breadcrumb from the route (Home,
  Administration › tab, Profile › tab, route title) or set by the page through
  `useTopBar().setCrumbs` (note pages: group › title, plus Editing); pages put
  their actions into it with `<Teleport defer to="#top-bar-actions">` (note
  view: Edit, Share, ⋯; editor: protect, Close, Save, ⋯; home: New note).
  `ViewNote` keeps its actions inline where there is no top bar (public
  page), detected through the `hasTopBar` provide. On a phone the bar shows
  the last crumb and, on note pages, a back button to the notes list.
- Note editor: tags as removable chips with an "Add tag…" field that keeps
  the tag autocomplete (`TagChipsInput`), a toolbar (bold, italic, heading,
  list, checklist, link, code, insert dialog; Write / Preview) and the
  editor in a bordered field. The floating insert button is gone; the
  toolbar opens the insert dialog. Editor colours follow the theme.
- `Dialog` takes an `icon` and a `#footer` slot (divider, buttons on the
  right, secondary first; full width and stacked on a phone). Every dialog
  uses it; form dialogs submit through `form="..."`.
- Users: filters above the table, initials avatars and role chips. Selected
  tree and list rows keep the strong blue of the design (`bg-sky-700/50`).
  List rows (reminders, shared, recycle bin, search, dashboard) show the icon
  in its own column with the title and a small detail line.
- Existing texts (titles, explanations, messages) keep their original
  wording; only new elements got new text.
- Second review (user): the note view and editor sit on a glass surface that
  always fills the height of the main area (the main area no longer has the
  sidebar's bottom padding). The editor is plain CodeMirror again, without a
  box or focus outline. Breadcrumbs are links: Administration and Profile go
  to their first tab, groups search the notes in that group (as clicking the
  group under a note title did), the note title in the editor goes back to
  the note. The group path comes from the loaded tree
  (`treeStore.groupPath`) and falls back to the note's own group; the same
  path replaces "→ in group" under the note title. Help and Insert open at
  80% of the window width on wider screens (`dialog-wide`).
- Lists stay in sync with note changes (user): `useNoteChanges` reloads a
  list once per burst of note responses (create, update, delete, restore,
  fully delete, revert to history; reminders where they matter; a "note
  shared" notification for the shared lists). Recently opened notes, current
  reminders and the sidebar reminders and shared lists use it instead of
  patching titles from `updateNoteResponse` only.
- Login (user): the sign-in form is a glass card centred vertically on the
  right (centred on a phone), with space above and below it, instead of a
  full-height side panel.
