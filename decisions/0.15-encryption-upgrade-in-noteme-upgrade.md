# 0.15 Encryption upgrade in noteme-upgrade

- Decided by: user (ask each user's password; plain visible stdin, no
  `golang.org/x/term`) and Claude (flow details)
- Date: 2026-10-19

`noteme-upgrade` always runs the encryption step last, also on a database
whose migration table is already converted.

- Users with `is_deleted = false` and an `encryption_key` without the `v2:`
  prefix are asked for their password one by one; the prompt shows how many
  protected notes and history entries they have.
- Input is a plain stdin line (visible). Empty line or end of input skips the
  user; 3 wrong passwords (checked with bcrypt) skip the user.
- Per user, in one transaction: decrypt the old key, generate a new v2 key,
  re-encrypt every `note` and `note_history` row with `is_encrypted = true`,
  non-empty text and no `v2:` prefix, then store the new key.
- Rows that do not decrypt with the user's old key (for example protected
  history from before an admin password reset, 0.9.t) are left unchanged and
  counted in the output; they were already unreadable.
- Safe to run twice: only users still in the old format are asked again.
- Deleted users are not converted.
