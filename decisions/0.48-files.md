# 0.48 Files

- Decided by: Claude (TODO item 14); user (login redirect for private files,
  Range support through `http.ServeContent`, dev-only Vite middleware for
  mock mode, files of deleted notes kept)
- Date: 2026-10-19

- `internal/components/storage` (on `components.Storage`) owns the temp
  folder (`Config.TempDir`, uploads as `<userId>-<uuid>`) and the files
  folder (`FILES_LOCATION`, files under their identifier, 0.3). The server
  creates both at start; the CLI and tests do not. Names with path
  separators, `.` or `..` are rejected. A finished upload is renamed into
  the files folder, or copied and removed when the folders are on different
  filesystems (a Docker volume).
- The `file.data` blob column is gone from the init SQL (edited in place).
  `noteme-upgrade` extracts the blobs, then drops the column and runs
  `VACUUM`; without the column a second run skips both.
- Uploads: `sendFileData` checks that the upload exists, is the user's and
  is unfinished, and checks the size before appending (0.9.j). `endFile` on
  a size mismatch removes the temp file and the record; otherwise it moves
  the file into the files folder and only then marks the record ready, so a
  ready record always has its bytes. Finishing an upload twice answers
  "File not found.". A cancelled upload leaves an unfinished record that no
  list shows; its temp file goes with the hourly `cleanup-temp-folder`
  (6 h).
- `GET /file/{identifier}[?download]` loads the session without requiring
  it. Public files open for anyone. A private file needs its owner or
  `canManageAllFiles`; a visitor without a session is redirected (303) to
  `/?redirect=<the file URL>` (user, target changed by 0.63), a logged-in user without access
  gets 403 "You do not have access to this file.". Unknown, unfinished or
  missing on disk: 404 "Requested file not found.". The response goes
  through `http.ServeContent` (user), which adds Range requests (206) and
  304 for `If-None-Match`; the ETag is the identifier in quotes, as HTTP
  requires (the original sent it bare). Fix over the original: private files
  are `Cache-Control: private` so shared caches never keep them; public
  files keep `public, max-age=604800, immutable`.
- The login page follows a `redirect` only when it is a path on this site,
  and loads `/file/...` targets as a full page, since the app does not
  route them.
- Docker: `/app` is root's, so `/app/data`, `/app/backup`, `/app/files` and
  `/app/temp` are created in the build stage and copied in owned by
  `nonroot`; `/app/files` is a volume.
- Mock mode (user): a dev-server-only Vite middleware serves `/file/<id>`.
  The mock backend runs in the browser, so on `endFile` it posts the bytes
  to `/__mock/files/<id>`; fixture files get a placeholder image. The
  `/file` proxy to the Go server is off in mock mode.
- Files of a deleted note stay, as in the original (user); the delete
  dialog lists the note's files with checkboxes to delete them with it.
  `NoteWindow` unlocks protected text for the Files and Delete windows too,
  as the original's wrapper did, because both look for file links.
- `tasks.Default` takes the components, since tasks now need storage too.
- Frontend: `FileSize`, `FileDropWrapper`, `UploadProgressDialog`,
  `FileUpload`, `FileItem`, `FilePicker` live in `components/files`;
  `useSelected` / `useListState` are not ported (plain refs). `Input` no
  longer accepts `type="checkbox"` (it bound a string); `Checkbox` is the
  checkbox.
