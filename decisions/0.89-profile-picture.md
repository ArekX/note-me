# 0.89 Profile picture

- Decided by: user (a profile picture that is one of the user's own files,
  so an existing image can be used); Claude (details below)
- Date: 2026-10-21

- `user.profile_picture` (nullable `varchar(255)`) holds the identifier of
  the picture's file. It has no foreign key: `file.user_id` already points
  at `user`, and a key back would make a cycle that the backup restore's
  table order cannot insert. Edited into the init migration of every
  driver; `noteme-upgrade` adds the column empty (`sqlite.UpgradeColumns`).
- `users/updateProfilePicture` `{identifier: string | null}` (not in the
  original) sets or removes it. Only the user's own finished image file
  (`image/*`) is accepted; anything else answers "File not found." or
  "Profile picture must be an image.". The session is refreshed, so every
  tab gets `sessionUpdated` with `user.profile_picture`; `/api/login` and
  `/api/session` send it too (`null` when unset).
- Deleting the file clears the picture in the same transaction and
  refreshes the owner's session, also when an admin deletes it. The
  picture keeps the file's visibility; it is only shown to its owner,
  who can always open their own files.
- Frontend: `UserAvatar` shows the image (`/file/<identifier>`) and falls
  back to the initials when it fails to load. The profile page has Add or
  Change picture, which opens `ProfilePictureDialog` (a `FilePicker` that
  starts on Images and can upload), and Remove. `FileViewDialog` has "Set
  as profile picture" for images outside admin mode.
