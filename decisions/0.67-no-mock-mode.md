# 0.67 No mock mode; the mock backend is test-only

- Decided by: user (remove the mock scaffolding; keep it as a test-only
  fake for the tests that use it); Claude (details below)
- Date: 2026-10-20

- The frontend always talks to the Go server. Removed: `VITE_SOCKET_MOCK`
  and `frontend/.env.development`, `src/lib/mock-mode.ts`, the `/app/dev`
  control page (`DevControlPage.vue`), the mock branches in the `socket` and
  `user` stores, `lib/api.ts` and `lib/passkeys.ts`, the Vite mock files
  middleware and `make dev-real` (`make dev` now proxies to the Go server).
- The mock handlers and fixtures moved from `src/lib/socket/mock` to
  `src/test/mock-backend` and are imported only by tests. Dev-page features
  (latency, offline, dropping the connection, raw pushes, log subscribers)
  are gone; the request log stays because tests assert on it.
- `src/test/setup.ts` assigns `MockWebSocket` to `globalThis.WebSocket`, so
  the app's own `browserTransport` talks to the fake backend, and resets the
  fixtures before every test. It is assigned, not `vi.stubGlobal`ed, so a
  test calling `vi.unstubAllGlobals` keeps it.
- Tests that used the HTTP mocks stub them directly: `PublicNotePage` spies
  on `api.getPublicNote` with `mockPublicNote`, `UserPasskeys` mocks
  `createPasskey` and `supportsPasskeys`.
- A new or changed websocket message no longer needs a mock handler; one is
  added to `src/test/mock-backend/handlers` only when a test needs it.
- The PWA note in 0.66 about mock mode no longer applies; the worker is
  still registered only in production builds.
