# 0.78 Skeleton loaders, upload dialog and periodic task runs

- Decided by: user (skeletons instead of spinners, including tables; the
  Upload button opens a dialog for several files with a list of them and
  each file's progress; checkboxes to change or delete several files; run
  history per periodic task for a period set by an env variable, readable
  names and descriptions, runs opened from a view icon); Claude (details
  below)
- Date: 2026-10-21
- Amends 0.55.

## Skeletons

- `Skeleton.vue` (`text`, `list`, `note` variants) and the `.skeleton`
  class in `styles.css`. Every placeholder has `role="status"` and
  `aria-busy="true"`; tests look for `[aria-busy="true"]`.
- `Table` shows `skeletonRows` (default 5) rows of bars while `isLoading`.
- A spinner that stood in for content being fetched became a skeleton
  shaped like that content. `Loader` stays only for actions in progress
  (saving, signing in or out, deleting, moving, unlocking, creating a
  backup): there is no content to sketch for those.

## Upload dialog

- In Files (admin) and My files the Upload button opens `UploadFilesDialog`:
  choose or drop files, see them with their size, remove one or clear all,
  then upload. Duplicates (same name, size and modification time) are added
  once. Dropping files on the page opens the same dialog with them added
  instead of uploading at once. The note file picker keeps the direct
  `FileUpload` button and `UploadProgressDialog`.
- After Upload the dialog stays open and shows each file's state from
  `useFileUploader().stateOf(file)`: waiting, a percentage and progress bar
  while uploading, uploaded, failed (with the server's message) or
  cancelled, plus "n of m uploaded". It cannot be closed while files are
  uploading; "Cancel upload" stops after the current chunk, then Close.

## Selecting files

- Admin Files and My files have a checkbox per row and a select-all
  checkbox in the header for the rows of the current page; the selection
  keeps only rows still shown after a page change, filter or reload.
  While something is selected a bar offers Make public, Make private,
  Delete (confirmed) and Clear selection.
- Bulk actions send one `updateFile` / `deleteFile` per file instead of
  `updateMultipleFiles`: that message only changes the caller's own files
  and records no audit entry, while the per-file handlers already apply the
  admin scope, the audit log and file removal. A failure is reported with
  the number of files that failed; the rest still change.

## Periodic task runs

- New table `periodic_task_run` (`task_identifier`, `ran_at`,
  `duration_ms`, `is_successful`, `fail_reason`, index
  `periodic_task_run_task_ran_at_index`) in the v2 migration of every
  driver, in `noteme-upgrade` and in `snapshotTables`. No foreign key: runs
  of a task that is no longer registered go with its schedule row in
  `DeleteUnusedPeriodicTasks`.
- `SavePeriodicTaskRun` records the run in the same transaction as the
  schedule update. After a tick that ran something, the scheduler deletes
  runs older than `PERIODIC_TASK_HISTORY_DAYS` (default 30, at least 1).
- Websocket `settings.getPeriodicTaskRuns` (`canViewPeriodicTasks`):
  `task_identifier`, optional `outcome` (`success` or `failed`), `page`;
  answers newest first with `runs` (paged, 20 per page) and `history_days`.
- Frontend: `src/lib/periodic-tasks.ts` holds each task's name, schedule
  and description (unknown identifiers show as they are). The task table
  shows them and a view icon that opens `PeriodicTaskRunsDialog` (time,
  outcome, duration, failure reason, outcome filter, paging).
