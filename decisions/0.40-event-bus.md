# 0.40 Event bus

- Decided by: user (after TODO item 7); implementation details by Claude
- Date: 2026-10-19

- Workers talk to the websocket through an in-process event bus instead of
  push functions wired in `internal/app` (replaces the `tasks.Notify` part
  of 0.39 and the "no message bus" rule).
- `internal/eventbus` is a leaf package: `Bus` with the generic methods
  `bus.Subscribe(fn)` and `bus.Publish(ctx, event)` (Go 1.27 allows type
  parameters on methods), keyed by the event's Go type. Event types live in
  `eventbus/events.go` so workers and the websocket share them without
  importing each other (first event: `NoteFullyDeleted{UserID, NoteID}`).
- Delivery is synchronous on the publisher's goroutine, in subscription
  order; an event with no subscriber is dropped. Nothing is persisted or
  retried.
- The bus is `components.Components.Bus`. The owning namespace's `Register`
  (0.41) subscribes and
  converts each event into the matching backend message (`hub.PushBackend`),
  so backend handlers stay the single path to the browser. `internal/app`
  creates the hub before the workers start so subscriptions exist before
  the first publish.
