# 0.4 Session semantics

- Decided by: earlier sessions (moved from TODO.md section 0)

The session row stores the slim user record
(no hash, no CSRF token), `expires_at` in ms, lifetime `CookieMaxAge`.
Role and `is_password_reset_required` are read from the session. The
frontend calls `/api/session` **once** on page load; every later change
is pushed over the websocket as `users/sessionUpdated` (item 2), so
there is no polling. Any change to a user's session data (own password
reset, profile, onboarding, or an admin changing their role or reset
flag) rewrites that user's session rows and pushes to all of their
connections, so it applies immediately (not at next login as in the
original).
