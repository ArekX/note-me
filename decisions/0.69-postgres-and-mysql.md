# 0.69 PostgreSQL and MySQL support

- Decided by: user (TODO item 28; drivers pgx and go-sql-driver/mysql; one
  shared repository with a dialect instead of a copy per driver; backups as
  a portable sqlite snapshot; Docker Compose for the tests); Claude (details)
- Date: 2026-10-20
- Amends 0.62 (the repository implementation no longer lives in the sqlite
  driver).

- `DATABASE_DSN` takes `postgres://` (also `postgresql://`, stored as
  `postgres`) and `mysql://user:password@host[:port]/database[?params]`;
  the part after `://` goes to the driver. MySQL needs 8.4 or newer
  (`JSON_VALUE ... RETURNING`, expression defaults).
- `database/sqlrepo` is the only repository implementation
  (`sqlrepo.New(db, databaseType)`). Queries keep `?` placeholders and
  "quoted" identifiers; the postgres driver wraps `*sql.DB`/`*sql.Tx` and
  rewrites `?` outside strings, identifiers and comments to `$n`; the MySQL
  connection runs with `sql_mode` `ANSI,STRICT_ALL_TABLES,NO_BACKSLASH_ESCAPES`
  and found rows (so `RowsAffected` counts matched rows as elsewhere).
- What still differs is in `sqlrepo/dialect.go`: `RETURNING "id"` vs
  `LastInsertId` (MySQL), tag aggregation, case-insensitive `LIKE`
  (`ILIKE`; `LOWER()` on MySQL, whose tables use `utf8mb4_bin` so `=` is
  case-sensitive like sqlite), null-safe equality, the note id inside
  notification JSON, the onboarding JSON merge and insert-or-ignore for
  passkeys.
- Queries rewritten once for all databases: search pages select ids
  through a derived table (MySQL has no `LIMIT` in `IN` subqueries); recently
  opened notes sort `last_open_at IS NULL` first instead of relying on where
  NULLs sort; the tree list returns `is_encrypted` as 0/1 via `CASE`;
  `SetReminder` updates and inserts when nothing matched (inside a
  transaction) instead of `INSERT ... SELECT ... WHERE NOT EXISTS`;
  `UpdateOnboardingState` updates and reads back in a transaction instead of
  `UPDATE ... RETURNING`.
- Each driver has its own `migrations/` with the same names. PostgreSQL uses
  identity `bigint` ids and `bytea`; MySQL uses `bigint auto_increment`,
  `longtext`, table-level foreign keys (InnoDB ignores inline ones) and an
  ascii `varchar` for the indexed passkey columns. `TestSchemaMatchesSqlite`
  compares tables, columns (kind, nullability, default present), unique
  columns, foreign keys and named indexes with the sqlite schema. The
  tracking table code is shared (`drivers.Migrations`); MySQL runs one
  statement per call, so its scripts end statements with `;` at a line end.
  MySQL commits DDL implicitly, so a failed MySQL migration is not rolled
  back. `new-migration` writes the pair to all three folders.
- Backups: the archive format stays the same and always holds
  `database.sqlite`. PostgreSQL and MySQL copy every row (in a read-only
  repeatable-read transaction) into a new sqlite database built by the sqlite
  migrations. `backups.RestoreInto` migrates the backup's database, clears
  the target and copies every row in one transaction (groups' `parent_id`
  is set after all groups are in), then moves PostgreSQL id sequences past
  the restored ids. `restore-backup` uses it for PostgreSQL and MySQL: it
  migrates the configured database and refuses one that already has users
  without `--overwrite`. A backup restores into any database type, which is
  also how to move between them. `noteme-upgrade` stays sqlite-only.
- Tests: `databasetest.Open`/`DSN` give each test its own database: a sqlite
  file, or with `TEST_DATABASE_DSN` a new PostgreSQL schema or MySQL
  database, dropped afterwards. `make test-databases` (part of `make test`)
  starts `compose.test.yaml` (postgres:18-alpine, mysql:8.4, data in tmpfs),
  runs the database, backup and CLI packages against each and removes the
  containers; `DOCKER=podman` works too. Every repository query runs in a
  test.
