# 0.34 Note and tag handlers

- Decided by: Claude (TODO item 4)
- Date: 2026-10-19

- New message `notes/getNote{id, mark_opened?}` → `getNoteResponse{record:
  ViewNoteRecord}`. The original loaded this record on the server for the
  view and edit routes; the SPA needs it over the websocket. Only the owner
  can load it; a missing, deleted or foreign note answers "Requested note not
  found." (the original route's 404 text). `mark_opened: true` sets
  `last_open_at`, which the original did only in the view route. The view page
  sends it, the editor does not.
- `getNoteDetails` does not touch `last_open_at` (the TODO text said it
  would): it also serves the Details and other note windows, which must not
  count as opening the note.
- `NoteDetailsRecord.group_id` / `group_name` are nullable: `null` when the
  note has no group or is someone else's shared note, `0` / `''` when
  `include_group` is off. The original returned the same at runtime while its
  type said `number` / `string`; both type definitions now say so.
- `createNote`, `updateNote` and `deleteNote` answer with `RespondToUser`, so
  other tabs update their tree and open note (as 0.32 for groups).
- Fix over the original: moving a note (`updateNote{group_id}`) checks that
  the group is the user's, like `createNote` already did ("Group does not
  exist!"). `updateNote` and `deleteNote` on a missing or foreign note answer
  "Note does not exist.".
- `UpdateNoteRequest.tags` is `*[]string` and `group_id` is
  `Optional[int64]`, so `[]` clears the tags (0.9.c) and `null` moves the note
  to the top level, while an absent key keeps them. `updated_at` changes only
  when title, text or `is_encrypted` is sent, as in the original; tag and
  group changes do not bump it. An empty `data` changes nothing and still
  answers `updateNoteResponse`, as the original did.
- Tag normalisation (lowercase, trim, remove spaces, dedupe) also drops empty
  names; the original stored a tag named `''`. `createTag` stores the name as
  given, as the original did.
- Validation: `validation.MaxItems` gives zod's `too_big` for arrays ("Note can
  have at most 20 tags"); an `Optional[T]` field reports `T`'s zod type in
  `invalid_type` messages.
