# 0.33 Optional and nullable fields in validation

- Decided by: Claude (TODO item 3; amends 0.16)
- Date: 2026-10-19

`updateGroup` needs `parent_id` to be absent (keep), `null` (top level) or a
number, and `createGroup` needs it required but nullable. 0.16 made every
pointer field optional and accepted `null` for any field, which cannot
express either. `validation.Decode` now reads the struct tags:

- A field is optional when its `json` tag has `omitempty` or `omitzero`;
  otherwise a missing key is an `invalid_type` issue.
- `null` is accepted only with `zod:"nullable"`; elsewhere it is an
  `invalid_type` issue ("received null"), as zod reports it.
- `error:"..."` replaces the `invalid_type` message, like zod's `{error}`
  parameter (`"Name is required"`).
- `MaxLength` adds `too_big` issues.

`messages.Optional[T]` (with `omitzero`) tells an absent key from `null` and
echoes the same shape back in `updated_data`.
