# 0.31 Tree store

- Decided by: Claude (user asked to improve the tree state handling)
- Date: 2026-10-19

The original kept the tree as nested objects, mutated them in place and then
deep-copied the whole tree through `JSON` to re-render; lookups walked the
tree; UI flags (`is_open`, `is_processing`, `display_mode`) were stored on the
records and persisted. `stores/tree.ts` replaces that:

- Nodes live in one map keyed `root` / `group-<id>` / `note-<id>` (unsaved
  editors `new-<uuid>`), each with a `parent` key and ordered `children`
  keys. Lookups by id, parent and ancestry are direct, and Vue tracks changes
  without copying.
- Open, processing and editing state are separate sets. Only nodes and the
  open set are persisted to `localStorage.treeStorage` (versioned snapshot);
  unsaved editors and spinners never are. Logout resets the store.
- Every change goes through a few idempotent operations (`attach`,
  `removeSubtree`, `setChildren`), used both by the requesting tab and by the
  live messages, so a response and its own broadcast never insert twice.
  A node arriving under a parent whose children are not loaded only marks the
  parent as having children.
- Groups stay sorted (groups before notes, by id, unsaved last).
- A restored tree is shown at once and refreshed in the background; Reload
  and Refresh re-fetch the level and every open level below it and drop
  closed levels, which load again when opened. The original kept a restored
  tree until a manual reload and Reload collapsed everything.
- The `groups` store stub is removed; group requests are tree store actions
  (`saveName`, `moveGroup`, `dropGroup`, `deleteGroup`). The delete progress
  is store state, not a component listener.
- Note entries in the tree menu, note rename and note drag come with item 4.

- Item 4: `dropGroup` became `dropItem` and `moveNote` was added; notes sync
  from the `notes` responses (0.36).
- Logout (`reset`) also clears the loaded state, so the next `init` after
  login loads the tree again; socket listeners are registered only once.
