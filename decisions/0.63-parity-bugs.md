# 0.63 Parity bugs

- Decided by: user (login redirect to `/` with only relative targets; no
  cookie domain setting; original S3 setups keep working); Claude (details,
  TODO item 23)
- Date: 2026-10-20
- Amends 0.48 (redirect target) and 0.56 (S3 keys).

- A visitor without a session asking for a private file is redirected to
  `/?redirect=<the file URL>`, the login page. The login page follows
  `redirect` only when it resolves to the same origin (`sameSitePath` in
  `src/lib/redirect.ts`); absolute, protocol relative (`//host`, `/\host`)
  and non-path values go to the dashboard.
- `COOKIE_DOMAIN` is removed. The session cookie has no `Domain` attribute,
  so the browser keeps it for the exact host that set it (not subdomains),
  which works behind any host name without configuration. A browser upgraded
  from the original can still hold its old `Domain` cookie with the same
  name and sends both, so the session loader tries every `session` cookie
  and uses the first one with a session.
- S3: new backups still go to `<trimmed prefix>/<identifier>` (or just the
  identifier). The original wrote `<prefix as entered>/<identifier>`, so
  when that differs (empty prefix, leading or trailing `/`) it is a second
  folder: listing reads both (one entry per identifier), download tries the
  new key first, delete removes both keys.
