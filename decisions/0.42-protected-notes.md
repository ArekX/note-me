# 0.42 Protected notes

- Decided by: Claude (TODO item 8)
- Date: 2026-10-19

- `users/encryptText` and `users/decryptText` open the user's note key with
  the sent password on every call (Argon2id, 0.14); the server never keeps
  the key or the password. A wrong password answers "Could not decrypt,
  wrong password or corrupted data."; a key or note value without the `v2:`
  prefix answers "Protected notes are stored in an old encryption format.
  Ask an administrator to run noteme-upgrade." (the original threw raw
  errors). These live in the new `users` namespace package (0.41).
- The lock state is the Pinia store `stores/protection-lock.ts`
  (`useProtectionLockStore`, global state belongs in stores) instead of the
  original's module-level hook; `AppLayout` calls `init()` and mounts
  `EncryptionLockWindow`. Kept from the original: the password stays in
  memory and in `localStorage.encryptionLock`, shifted by `startAt` and
  base64-encoded. That is obfuscation, not encryption; the lock exists so
  the password is not asked for every note. Logout locks before clearing
  storage.
- `LockedContentWrapper` decrypts copies of the records (the original
  changed its input records in place), takes the records through a scoped
  slot, and ignores results of runs that a newer run or a lock replaced. It
  watches the `records` array by reference, so callers pass a computed
  array, not an inline literal.
- Toggling Protect in the editor marks the note as changed, so leaving
  without saving asks for confirmation; the original lost the toggle
  silently. Save encrypts the text first; a cancelled unlock shows as an
  error toast and nothing is saved.
- Mock fixtures store protected text as `mock:` + base64 so the mock can
  decrypt it with the mock password (`admin`); mock errors use the server's
  texts.
