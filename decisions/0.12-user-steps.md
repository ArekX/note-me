# 0.12 User steps

- Decided by: earlier sessions (moved from TODO.md section 0)

Password reset becomes a *step*, processed over
HTTP by `POST /api/process-step` (item 1), not over the websocket
(`/ws` stays behind `UserStepsRequiredMiddleware`, so a user with a
pending step cannot open a socket). Request `{step, action, data}`; the
server keeps a registry `step → action → {schema, handler}` and each
action declares what it requires. A step is either *required* (blocks
the app until done; today only `password_reset`, derived from
`is_password_reset_required`) or optional. This is also the first-time
setup flow: a new account (the item 1 bootstrap admin, or a user an
admin created) starts with its required steps pending and walks through
them on first login; more setup steps (e.g. timezone) are added as new
registry entries. The intro-tour flags (`onboarding_state`,
`users/updateOnboarding`) are unrelated and stay as in the original.
