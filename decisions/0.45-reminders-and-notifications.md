# 0.45 Reminders and notifications

- Decided by: Claude (TODO item 11)
- Date: 2026-10-19

- Notifications are stored as the original's JSON `{type, payload}` in
  `notification.data`; the repository keeps it as a string and the
  `notifications` namespace decodes it into `messages.NotificationRecord`.
  Every payload's `id` is a note id, so `FullyDeleteNotes` deletes a note's
  notifications with `json_extract(data, '$.payload.id')` (0.9.f).
- Whoever creates a notification publishes `eventbus.NotificationCreated`
  (id, user, data JSON, created_at); the `notifications` namespace turns it
  into the backend message `addNotification`, which pushes
  `notificationAdded` to the user (0.40, 0.41). Item 12's share
  notifications use the same event.
- `check-reminders` creates the notification and resolves the reminder's
  next occurrence in one transaction, then publishes the event; a failing
  reminder is logged and the rest continue. `GetReadyReminders` skips
  reminders of deleted notes (0.9.h); they fire once the note is restored.
- `setReminder` checks ownership first (as the original), then validates.
  The reminder union matches zod 4: no matching branch gives one
  `invalid_union` issue on `reminder` ("Invalid input"); the repeat branch
  then reports `too_small` per field. The branch objects accept extra keys,
  as the original schema did. Set, remove and the shared-note access of
  item 12 aside, scheduling is as the original (minute truncation, upsert
  keeping `done_count`, next run from now per 0.9.m).
- `setReminder` and `removeReminder` answer all of the user's tabs
  (`RespondToUser`).
- The reminder window stays open when the entered date is missing or past
  or the interval is invalid (the errors are shown); the original closed it
  and dropped the reminder silently.
- `PassedReminders` reads the notifications store instead of requesting
  `getMyNotifications` again; deleting goes through the store so the bell
  and the dashboard stay in step. The store clears and stops listening on
  logout (`reset`), asks for the OS notification permission after the
  first load and shows an info toast and, when allowed, an OS notification
  for each pushed notification.
