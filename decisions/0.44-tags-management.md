# 0.44 Tags management

- Decided by: Claude (TODO item 10)
- Date: 2026-10-19

- `updateTag` validates first and then requires `canUpdateTags`, as the
  original; `deleteTag` requires it and removes the tag's note links and the
  tag in one transaction. A rename stores the name as given, like
  `createTag` (0.34); renaming to an existing name leaves two tags with that
  name, as in the original.
- Settings tabs are one list (`lib/settings-tabs.ts`, name, route,
  permission) used by `SettingsLayout` and by the route guard. A settings
  route whose permission the user lacks redirects to the first tab they may
  open (the original answered 403); with none left, to the dashboard.
- `EditTagForm` validates with `addTagSchema` for a new tag and
  `updateTagSchema` for an existing one before sending (the original only
  validated on the server); server validation errors show in the form,
  other errors as a toast.
- Mock handlers can check permissions through `missingPermission` in
  `mock/handler.ts`, which uses the role table in `lib/rbac.ts` and the
  server's error text; the tag mocks use it and apply renames and deletes
  to the notes' tags.
