# 0.58 Help and onboarding

- Decided by: Claude (TODO item 20)
- Date: 2026-10-19

- `updateOnboarding{onboarding_state}` merges only the given keys into the
  stored JSON (SQLite `json_patch`); the original replaced the whole object
  with what the tab sent, so two tabs could undo each other's dismissals.
  The object is strict (the four known keys, booleans); unknown keys are an
  `unrecognized_keys` issue. The response carries the merged state and every
  tab gets the new session (`RefreshUserSession`).
  `backup_management_intro_dismissed` stays an accepted key though nothing
  shows that intro, as in the original.
- Help: `HelpWindow` (in the app layout) with the 13 pages as components;
  `HelpButton` in both sidebar menus, a "Help" item in the note MoreMenu for
  every mode, `HelpAction` for links to a help page and `HelpLink` for links
  to an app page (following one closes the help). Pages are opened by key
  through the `help` store instead of the original's `open-*` action names.
- The text is the original's with spelling fixed and the insert dialog
  described as Alt+I in the bottom right corner (0.9.v). The keyboard
  shortcuts page is generated from the hotkey maps the editor uses, and the
  supported languages page from the highlight.js bundle that renders code
  blocks (the original kept a hand-written copy of about 170 languages).
- Onboarding: one `OnboardingDialog` (the original's dialog and wrapper)
  with "Don't show this again" (stored) and "Close" (only this page);
  `DashboardIntroduction` on the dashboard, `ViewNoteIntroduction` on the
  note view, `EditNoteIntroduction` on the new and edit note pages.
