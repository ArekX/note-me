# 0.14 Note encryption format v2

- Decided by: user (upgrade to the strongest current scheme; no compatibility
  with the old format after the upgrade) and Claude (algorithms, parameters,
  layout)
- Date: 2026-10-19

The server reads and writes only format v2 (`internal/encryption`). The
original format (PBKDF2-SHA256 500000 iterations + AES-256-GCM, a 64-byte key
used as the PBKDF2 password for every note) exists only in
`cmd/noteme-upgrade/legacy.go`, which converts it (0.15).

- Stored values are `"v2:" + base64(...)` (standard alphabet). `:` never
  occurs in base64, so a value without the prefix is unambiguously old.
- User note key: 32 random bytes. `user.encryption_key` =
  `v2:` + base64(salt(16) || nonce(24) || XChaCha20-Poly1305(key) || tag(16)),
  sealed with a key from **Argon2id** (t=3, m=64 MiB, p=4, RFC 9106 second
  recommended option) over the password; additional data `noteme:v2:key`.
- Note text: `v2:` + base64(nonce(24) || XChaCha20-Poly1305(text) || tag(16))
  sealed directly with the note key; additional data `noteme:v2:note`. No
  per-note password derivation (the old scheme ran PBKDF2 for every note).
- Argon2id parameters belong to v2; changing them needs a new prefix.
- API: `GenerateNoteEncryptionKey`, `ReEncryptNoteKey`, `OpenNoteKey`,
  `EncryptNote(key, text)`, `DecryptNote(key, value)`, `IsCurrentFormat`.
  Item 8 builds `encryptText`/`decryptText` on `OpenNoteKey` + these.

Why: Argon2id is OWASP's first choice for password hashing (memory-hard, so
GPU/ASIC guessing costs much more than PBKDF2). XChaCha20-Poly1305's 192-bit
random nonce removes the nonce-collision limit of 96-bit GCM nonces. Both come
from `golang.org/x/crypto`, which is already an approved module (bcrypt).

Consequences: every Argon2id run allocates 64 MiB, so concurrent unlocks cost
memory. A user whose key is still in the old format (skipped in the upgrade)
cannot change their password or open protected notes until the upgrade is run
again for them.
