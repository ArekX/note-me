# 0.16 Validation helper

- Decided by: Claude (TODO item 1 left the strictness choice open)
- Date: 2026-10-19

`internal/http/validation` produces 0.8 issues (`{code, path, message}`), with
messages checked against zod 4 output.

- Unknown JSON keys are **rejected**, like the original strict zod schemas:
  one `unrecognized_keys` issue, message `Unrecognized key: "x"` /
  `Unrecognized keys: "x", "y"`. Applies to every later schema.
- `Decode` handles structure (not an object, unknown keys, wrong types,
  missing non-pointer fields; pointer fields are optional). Amended by
  0.33: optional and nullable come from struct tags. When it reports
  issues they are returned alone and field rules do not run. zod also skips
  refinements after these failures, but it would still list `too_small`
  issues of other fields; that difference is accepted.
- String lengths count UTF-16 code units, like zod.
- Schemas live next to their handler as a request struct with a `validate()`
  method using `MinLength` / `Custom`.
- HTTP validation failures answer 400 `{"error": "<issues JSON>"}`, the same
  string the websocket puts in `message`. The frontend parses it with
  `parseValidationIssues` (`lib/error-messages.ts`).
