# 0.57 Database holds file metadata only

- Decided by: user
- Date: 2026-10-19

- The database keeps only file metadata (`identifier`, `name`, `size`,
  `mime_type`, owner, flags, `created_at`); the bytes live in
  `FILES_LOCATION/<identifier>` (0.3, 0.48). There is no `file.data` column.
- Databases that still have `file.data` (original databases converted by an
  older `noteme-upgrade`) are fixed by running `noteme-upgrade` again: it
  extracts any remaining blobs to `FILES_LOCATION`, drops the column, runs
  `VACUUM` and now also a `wal_checkpoint(TRUNCATE)`, without which the
  compacted database stays in the `-wal` file and the database file keeps
  its old size while the server has it open.
- Backups pack the database and the files together in one zip and restore
  both (0.56).
- `.env.defaults` sets `FILES_LOCATION=files`, so development keeps uploads
  in `./files` next to `database.sqlite`. Without it the default (next to the
  executable) put them inside Go's build cache under `go run`, a new folder
  on every rebuild, so uploads seemed to vanish and backups had no files.
  Docker is unaffected (`/app/files`).
