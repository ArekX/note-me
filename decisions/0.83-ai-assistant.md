# 0.83 AI assistant

- Decided by: user (TODO item 29 design and its open questions: chat only
  in the panel, a deleted provider's overrides become No AI, API keys
  encrypted with a required `AI_ENCRYPTION_KEY`, conversations left out of
  the data export, protected notes through a consent dialog per
  conversation); Claude (details below)
- Date: 2026-10-21
- Builds on 0.85 (live updates).

- **Where the model runs**: the server calls the provider and streams the
  answer; the API key never reaches the browser. Tool calls go to the
  browser, which runs them as ordinary websocket messages under the user's
  session, so every handler checks them as usual. The server never runs a
  tool. Native tool calling of each provider (OpenAI `tools`, Claude
  `tool_use` / `tool_result`, Ollama `tools`); Claude gets `max_tokens`
  8192. Providers are called with `net/http` (SSE for OpenAI and Claude,
  NDJSON for Ollama); no new library.
- **One source for tools**: `internal/http/aitools` holds 63 tools in one
  file per area. A tool's argument struct gives both its JSON schema (from
  the `json`, `zod`, `desc` and `enum` tags) and its validation (0.16).
  `Prepare` turns arguments into the websocket message (namespace, type,
  expected response, payload, an optional longer timeout), and `Result`
  trims the response (no header, no protected search snippets). The
  server validates and prepares each call and sends the prepared message
  in `toolCallsRequested`. The browser only sends it back as the user and
  returns the raw response, so request building and trimming stay in Go.
  `getTools` gives the browser the titles for stored steps. Browser-only
  tools: `open_note`, `open_help`, `list_help_topics`, `get_help_topic`
  (the topics `HelpWindow` shows this user, from
  `components/help/help-topics.ts`, rendered off screen to text),
  `get_profile` and `set_note_protection`. Item 30 runs the same catalog on
  the server.
- **Differences from the item text**: `update_file` only changes
  visibility (files cannot be renamed); `update_user` has no password,
  `create_user` takes the initial password; `get_shared_note` reads a note
  shared with the user. Never offered: uploads, password changes (the
  `update_profile` arguments have no password fields), import (export
  since 0.90),
  the server log, AI providers and AI access.
- **Editor and passkeys** (user, amends "never passkeys" above):
  `update_profile` also sets `preferred_editor`; `get_passkeys` lists
  passkeys; `add_passkey` and `delete_passkey` are browser tools that
  always ask for the password in `AiPasswordDialog` (checked with
  `verifyOwnPassword`, so wrong passwords count toward the lock), whatever
  the server's five minute confirmation says. `add_passkey` then runs the
  device's passkey prompt and names the new passkey; a closed prompt or
  password box is a declined step.
- **File mentions** (user): files are written as `[name](/file/<id>)`, which
  open in a new tab like any link in an answer.
- **Live status** (user): while this tab runs a turn, a pill with animated
  dots says "Thinking", "Working" (a step runs), "Waiting for you" (Allow /
  Deny) or "Writing"; reduced motion keeps the dots still.
- **Changes from the assistant count as made elsewhere**: the browser sends
  tool messages with `notOwn`, so they are not this tab's own requests
  (0.85). An open note reloads (and decrypts) or shows the conflict banner,
  and lists that skip their own requests still reload.
- **Confirmation**: tools that cannot be undone or that reach other people
  wait for Allow / Deny in the step list; Deny answers "The user declined
  this action."
- **Protected notes**: `get_note` and `get_history_version` decrypt in the
  browser, `update_note` encrypts new text of a protected note, and only
  after `ProtectedNotesConsentDialog` (yellow warning that the data goes to
  the provider, "Your password is never sent to the AI."). Locked: a
  password field and "Unlock and allow for this conversation". Unlocked:
  Allow is disabled for 5 seconds with a countdown. The grant lives in the
  `aiConsent` store for one conversation in one tab. A locked protection
  asks for the password again. `set_note_protection` with protection
  locked answers "Protected notes are locked. Ask the user to unlock them
  first." without a dialog. A decrypted result is marked `protected`: the
  model gets it within the turn, but the stored tool message holds
  "[Protected note content is not stored.]".
- **Access**: the user's own setting (a provider or No AI), else the
  default provider, else none. It is read on every `ai` message, not kept
  in the session. Provider updates, deletes and default changes push
  `ai/accessChanged` to every connected user; a per-user change pushes it
  to that user. Other admins get `dataChanged` for `aiProvider` and `user`.
- **Locked conversations**: a conversation keeps its provider id, name and
  model. It is locked when the user's provider is another one or gone; a
  model or key change keeps it open. Turns use the provider's current
  model.
- **Turns**: one goroutine per turn under the connection's context, so a
  closed connection cancels it. Pushes go only to that connection, and
  other tabs follow `conversationUpdated`. Limits: one turn per
  conversation, 25 tool rounds, 20 000 characters per tool result, 10
  minutes for tool results. A cancelled turn keeps the partial answer and
  answers pending calls with "The turn was cancelled before the tool ran."
  Text chunks go out at most every 50 ms, since a full outbound queue
  drops the connection. Calls with an unknown name or bad arguments are
  answered on the server.
- **Base URLs** (user: Ollama's cloud by default): an empty base URL takes
  the type's default, `https://ollama.com` for Ollama (a local server is
  entered as `http://localhost:11434`), `https://api.openai.com/v1` and
  `https://api.anthropic.com`, so no base URL is required. The Ollama key
  stays optional for local servers.
- **API keys**: `encryption.EncryptSecret` / `DecryptSecret`: `v2:` +
  base64(salt(16) || nonce(24) || XChaCha20-Poly1305 || tag(16)), the key
  Argon2id over `AI_ENCRYPTION_KEY` (0.14 parameters), additional data
  `noteme:v2:ai-key`. Opened keys are cached per provider and sealed value.
  The server refuses to start without the variable. A key that does not
  open is shown as "API key cannot be decrypted, enter it again"; tests and
  turns fail with that message. Keys are never sent back; an empty key
  field keeps the stored one.
- **Schema** (initdb, every driver, `noteme-upgrade`, `snapshotTables`):
  `ai_provider` (unique name), `ai_user_access` (an `id` like every other
  table, the backup copy and sequence reset need it, plus a unique
  `user_id`), `ai_conversation`, `ai_message`. Like the rest of the schema,
  foreign keys have no ON DELETE: deleting a user or a provider clears the
  rows in its transaction.
- **UI**: rail and phone menu entry "AI" (`bot`) below the recycle bin, only
  with access. The sidebar panel holds the conversation list (`SidebarList`
  over `useLoadMore`, rename, delete) and the open conversation. The
  composer sends with Enter (Shift+Enter for a new line) and offers Stop
  while running. Each answer's steps form one collapsed group, which opens
  by itself while a step waits. Below it, every note `create_note` made
  gets a card with its title and "Note created" that opens the note (user),
  read from the step's result, so stored conversations show it too.
- **Open page** (user): each `sendMessage` carries `page` (route name and
  note id). The server turns it into one line of that turn's instructions
  ("their note #12 titled \"Plan\" (viewing it)", "Settings → Users", ...):
  note titles come from the database scoped to the user, a note the user
  cannot see gives no line, and the title is quoted as data. The note's
  text is never sent this way; the model reads it with `get_note`, behind
  the protected notes consent. Unsaved editor changes are not included.
- **Tag mentions** (user): the system prompt asks for tags as
  `[#tag](#tag:tag)` (spaces as `%20`). In answers such a link is shown like
  a note's tag and runs the same tag search; the sidebar switches to Notes,
  where the results show, since the AI panel would cover them.
- **Conversation titles** (user): a new conversation starts with its first
  line as the title, and the same provider is asked for a title of at most
  six words next to the first answer (no tools, one minute, the first 2000
  characters of the message as data). The answer is cleaned (quotes, a
  "Title:" label, markdown, a full stop), saved unless the user renamed the
  conversation meanwhile, and pushed with `conversationUpdated`. A failure
  keeps the first-line title. The conversation list header says "AI
  Assistant" without the provider and model.
- **Note mentions** (user): the system prompt asks the model to write the
  user's own notes as `{:note-link|<id>}`, which shows the live title as a
  link, and notes shared with the user as `[title](/app/note/shared-<id>)`.
  In answers, links to `/app/` open in place (a modifier key keeps the new
  tab); note links close the phone menu like the sidebar lists. Settings → AI lists the providers; the user
  form gets "AI access" and the user list an AI column.
- Admin changes are recorded in the audit log (`ai_provider_created`,
  `ai_provider_updated`, `ai_provider_deleted`,
  `ai_default_provider_changed`, `ai_access_changed`).
- **Provider hidden from users** (user): users are not told which provider
  or model they use. `getAccess` answers only `enabled`, conversation
  records carry no provider name or model, the conversation header shows
  only the title, the protected notes dialog says the data goes to "the AI
  provider", and a locked conversation says "Your AI access changed, so this
  conversation can be read but not continued." The provider name and model
  stay in the database for admins and the lock check.
- **Default in the form** (user): the provider form has a "Default
  provider" checkbox (ticked for the first provider) next to the star in
  the list. Saving sends `setDefaultProvider` after the create or update
  when the box differs from the saved record.
