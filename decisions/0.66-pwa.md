# 0.66 PWA support

- Decided by: user (make the frontend installable as a PWA, TODO item 27);
  Claude (details below)
- Date: 2026-10-20

- No new dependency (no `vite-plugin-pwa`): a hand-written
  `public/manifest.json` and a small service worker in
  `src/service-worker.js`. The manifest is `.json`, not `.webmanifest`, so
  Go's built-in MIME table serves it as JSON on every OS and in the
  distroless image without a backend change.
- Manifest: name NoteMe, `start_url` and `id` `/app` (the router sends a
  visitor without a session to the login page), scope `/`, standalone,
  background and theme colour `#040613` (the `night` token). `index.html`
  links it and sets `theme-color` and `apple-touch-icon`.
- Icons in `public/icons` are generated once from `logo-white.svg` on
  `#040613` with ImageMagick: `icon-192.png` and `icon-512.png` (rounded
  tile, logo at 70% height, `any`), `icon-maskable-512.png` (full bleed, logo
  at 50% height so it stays in the maskable safe zone), `apple-touch-icon.png`
  (180 px, full bleed, iOS rounds it).
- The worker is registered only in production builds (`import.meta.env.PROD`)
  so mock mode and the Vite dev server are never cached. Browsers only allow
  it on HTTPS or `localhost`; over plain HTTP the app still works, it just
  cannot be installed.
- Caching: `/api/`, `/file/` and `/ws` are never intercepted or cached (user
  data and downloads), nor are non-GET or other-origin requests. Page
  navigations are network first and keep the last `index.html` for an
  offline start. Hashed `/assets/*` are cache first. Other public files
  (fonts, wallpapers, icons) are served from the cache and refreshed in the
  background. HTML answering a non-navigation request (the server's SPA
  fallback for a missing file) and redirected responses are not cached.
- The `noteme-service-worker` Vite plugin emits `sw.js` with the cache name
  `noteme-<hash of the bundle file names>`; the new worker skips waiting,
  claims open pages and deletes the older `noteme-*` caches. There is no
  "update available" prompt: the next navigation already loads the new
  `index.html` from the network.
- Offline the app shell loads but shows the existing connection state; notes
  are not available offline.
