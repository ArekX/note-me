# 0.62 Repository interface and database drivers

- Decided by: user (repository as an interface, implementation in a sqlite
  driver at `drivers/sqlite/sqlite.go` together with its migrations, migrator
  working through an interface); Claude (details)
- Date: 2026-10-20
- Amends 0.13 (the transaction callback takes the interface).

- `internal/components/repository` holds only interfaces, the record and
  filter types, `Paged` and the errors. Consumers use `repository.Repository`
  (no pointer). This is the first step towards other databases (e.g.
  MySQL); the SQL itself is unchanged.
- The methods are split into one interface per namespace, following the
  repository files: `BackupTargets`, `Files`, `Groups`, `Notes`,
  `NoteHistory`, `Reminders`, `Search`, `Shares`, `Notifications`,
  `Passkeys`, `PeriodicTasks`, `Sessions`, `Tags`, `Tree`, `Users`,
  `UserManagement`, each in its domain file. `Repository` has
  `RunInTransaction` plus an accessor per namespace
  (`repo.Notes().GetNote(...)`, `tx.Tags().LinkNoteWithTags(...)`). Go
  interfaces cannot have fields, so accessors are methods; they return
  the same object, not a new one (the sqlite repository returns itself).
- `internal/components/database/drivers` keeps the `DB`/`Tx` interfaces.
  `drivers/sqlite` holds the connection (`sqlite.Open`, which also registers
  `modernc.org/sqlite`), the repository implementation
  (`sqlite.NewRepository` returns `*sqlite.Repository`) with its tests, the
  migration driver (`sqlite.NewMigrations`) and the embedded `migrations/`
  folder.
- `RunInTransaction(ctx, func(tx repository.Repository) error)` is the public
  form. Inside the driver, methods use the unexported
  `runInTransaction(ctx, func(tx *Repository) error)` so they keep `tx.q` and
  unexported helpers. Nesting and the 0.13 rules stay the same.
- `migrate.Migrator` is driver-independent. It reads migration files from
  `Driver.Files()` (under `migrations/`), and the driver applies and reverts
  scripts and keeps the tracking table (`Applied`, `Apply`, `Revert`).
  `Driver.UpgradeReason` reports the driver's own leftovers of older schemas
  (for sqlite the original app's migration table, file blobs and passkeys).
  The migrator adds the check for recorded migrations that no longer exist.
- `database.Open(ctx, cfg)` switches on `cfg.DatabaseType` and returns
  `*database.Database` with `DB`, `Repository` and `Migrator`.
  `components.Components` gets a `Migrator` field, which the server start and
  `noteme-cli migrate-up/down` use.
- `noteme-upgrade` stays sqlite-only and uses `sqlite.Open` and
  `sqlite.NewMigrations` directly. Backups (`VACUUM INTO`) still take a
  `drivers.DB` and remain sqlite-specific.
- `new-migration` writes to `internal/components/database/drivers/sqlite/migrations`
  by default.
