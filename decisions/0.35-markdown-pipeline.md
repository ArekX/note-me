# 0.35 Markdown pipeline

- Decided by: Claude (TODO item 4; implements 0.10)
- Date: 2026-10-19

`src/lib/markdown.ts` parses with `markdown-it` (`html: false`) and
`markdown-it-footnote`, then builds the original's syntax tree (same node types
and data) from the token stream.

- Extensions `{:name|param|...}` are an inline rule before markdown-it's
  `text` rule (`{` is one of its terminators). `\{` needs no special case:
  the escape rule turns it into a literal `{` first. Code spans keep the
  braces as code. The limits stay: `note-list` 10 and `note-link` 20 per
  note, further ones become `over-limit` with `[name, count, limit]`.
  `params` keeps the original's split, so `{:table-of-contents}` has `[""]`.
- Task list markers (`[ ]`, `[x]`, `[X]` followed by whitespace) are a core
  rule after `text_join` on the first inline of a list item paragraph.
- Differences from the pulldown-cmark stream: footnote definitions come in a
  trailing block (after the content) instead of in place; inline footnotes
  `^[text]` work and are labelled by their number; hidden paragraphs of tight
  lists are skipped, `tbody` and the head row are folded away so head cells
  sit in `tableHead` and rows in `table`.
- Heading ids are computed from the node text (text and inline code) instead
  of the rendered DOM; the table of contents uses the same text, so its links
  match the ids. The original's ToC left inline code out of the heading text,
  so headings with code had links that did not match.
- `markdown-it` 15 ships its own types, so `@types/markdown-it` (listed in
  0.10 / 0.11) is not installed; `markdown-it-footnote` has none and gets a
  module declaration in `env.d.ts`.
