# 0.43 Note history

- Decided by: Claude (TODO item 9)
- Date: 2026-10-19

- `updateNote` and `revertNoteToHistory` share one update routine that
  first snapshots the note as it is (`AddHistory`) and then applies the
  change, all in one transaction. An empty update changes nothing and adds
  no version, as in the original (the TODO said "always"); a move or a
  tag-only change does add one, as in the original.
- Version names count existing rows ("Version N", "(before reversal)"), as
  in the original, so a deleted version's number can be reused.
  `FindHistory` orders by `created_at DESC, id DESC` so versions saved in
  the same second keep their order.
- Fix over the original: `revertNoteToHistory` only accepts a version that
  belongs to the given note ("Note history data does not exist."); the
  original reverted note A to a version of the user's note B. A revert or a
  deleted version goes to all of the user's tabs (`RespondToUser`).
- `diffText` uses jsdiff's `diffArrays` over the split lines (the TODO named
  `diffLines`, whose chunks carry trailing newlines); the output and the
  removed-then-added pairing as "changed" are as the TODO describes (0.11).
- The history window's view switcher shows labels at every width; the
  original showed icons only between `md` and `lg`. The history preview is
  `ViewNote` with `historyMode` (no actions, no live updates, tags not
  clickable).
- The mock history now behaves like the server: snapshot before the
  update, no version on create, the same names and error texts.
