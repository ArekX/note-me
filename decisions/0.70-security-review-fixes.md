# 0.70 Security review fixes

- Decided by: user (which findings of the security review to fix and how,
  recorded as "Alex decision" under each finding in `SECURITY_FINDINGS.md`);
  Claude (implementation details)
- Date: 2026-10-21

A seven-pass security review of the Go rewrite produced the findings
SF-01 to SF-50. This decision records what was done with each one; the
larger changes have their own records (0.71 to 0.77).

## Declined

| Finding | Decision |
| ------- | -------- |
| SF-02 login limiter keyed by address | Kept as it is (0.51); an attacker who can rotate addresses can flood the server anyway. |
| SF-07 unlimited concurrent exports | No export cap. `MAX_ALLOWED_BACKUP_COUNT` already limits backups per target and removes the oldest automatic ones, which is the limit the original app had. |
| SF-14 security response headers, CSP, HSTS | Not added. |
| SF-43 `new-migration` name sanitising | Developer command, left alone. |
| SF-45 / SF-46 S3 secret at rest, IAM role targets | The S3 secret stays in plain text in `backup_target.settings` (there is no key to protect it with that an admin could not also read); IAM role targets stay because the original app had them. |
| SF-48 global tags, user picker enumeration, admin file visibility, export size | Kept as designed. |
| SF-50 container and CI hardening | Not changed. |

## Fixed

| Finding | What changed |
| ------- | ------------ |
| SF-01 | Local backup targets live under `LOCAL_BACKUP_ROOT_LOCATION` (0.73). |
| SF-03 | Logout, session expiry, forced password reset and password change reach open websockets (0.75). |
| SF-04 | bcrypt is gone from the app, passwords are Argon2id, and a signed in user's password checks are limited per user (0.71). |
| SF-05 | Users are deleted for good (0.72). |
| SF-06 | A revoked share takes the recipient's reminder and notifications with it (0.77). |
| SF-08 | `cleanup-temp-folder` also removes `file` rows of uploads that never finished; `MAX_USER_STORAGE_SIZE` (bytes, 0 = unlimited) caps a user's uploads. |
| SF-09 | `MAX_CONNECTIONS_PER_USER` (0 = unlimited) and a per-connection outbound queue, so a stalled client never blocks a worker (0.75). |
| SF-10 | A panicking periodic task is recorded as a failed run and the schedule moves on; `restore` retries with backoff; a panic in a websocket handler closes only that connection. |
| SF-11 | Backups are encrypted, hold no sessions and are never world-readable on disk (0.73). |
| SF-12 | Mermaid runs with `securityLevel: "strict"` and HTML labels off, so HTML in a diagram is text; no sanitiser library. |
| SF-13 | Log values with control characters are quoted and long values cut; unknown websocket namespace and type are cut before logging. |
| SF-15 | Protected notes cannot be shared; protecting a shared note removes every share (0.77). |
| SF-16 | Pages start at 1 and a page past the end answers an empty page. |
| SF-17 | Id lists carry `MaxItems`, names and titles `MaxLength` matching the smallest column (255, username 60). |
| SF-18 | Reminder interval, unit and repeat count are capped and a reminder must lie in the future. |
| SF-19 | An unknown username still runs the password hash, so timing says nothing (0.71). |
| SF-20 | Passwords are at most 128 characters on every path; `noteme-cli add-user` reads the password from stdin and applies the same rules. |
| SF-21 | A full passkey challenge store refuses new sign-in ceremonies instead of evicting live ones; the sign-in ceremony lasts 2 minutes. |
| SF-22 | Private files are served with `Cache-Control: private, no-store`. |
| SF-23 | A manual backup claims the target before building the archive; archive builds are serialised. |
| SF-24 | Backup handlers answer fixed texts and log the cause. |
| SF-25 | Files are written 0600, folders 0700. |
| SF-26 | Restore validates the database entry first, bounds every entry by its declared size, stages files and takes column names from the app's own schema. |
| SF-27 / SF-42 | Unique indexes where the code checked before inserting; MySQL `INSERT IGNORE` is gone (0.76). |
| SF-28 | Bad environment values are errors; `APP_URL` needs `http(s)://host`; `SERVER_ADDRESS` defaults to loopback in `.env.defaults`. |
| SF-29 | Shutdown logs every connection out, waits for handlers, then closes the database (0.75). |
| SF-30 | Websocket reconnects back off exponentially with jitter, flapping counts as retries, the pending queue is capped. |
| SF-31 | Heading ids are `note-h-<slug>` and footnotes `note-footnote-<label>`, so note content cannot shadow app elements. |
| SF-32 | `IdleTimeout` and a 30 s `http.TimeoutHandler` on the JSON routes. |
| SF-33 | Logout clears the cookie whether or not the session is valid. |
| SF-34 | Export downloads accept only UUID identifiers. |
| SF-36 | The initial password is no longer written to the log; it is documented. |
| SF-37 | The last administrator cannot be demoted or deleted. |
| SF-41 | A protected note that could not be converted by the upgrade says so instead of asking for another upgrade run. |
| SF-44 | File names reject `:` and the Windows reserved device names. |
| SF-47 | Every `target="_blank"` link carries `rel="noopener noreferrer"`. |
| SF-49 | Audit log and server log (0.74); log lines carry the date. |
